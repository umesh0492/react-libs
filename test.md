## 1. Test Architecture

The library uses a **two-layer testing strategy**:

| Layer | Tool | Scope | Runner |
|---|---|---|---|
| **Unit tests** | Vitest + jsdom | `src/**/__tests__/**/*.test.{tsx,ts}` | Node process |
| **Interaction tests** | Storybook 10 + Chromium | All `*.stories.tsx` `play()` functions | Real browser (Playwright) |

Both layers are run together via `npm run test` and are enforced in CI on every push to `main` and every tag push (`v*`).

### Directory Layout

```
src/
  components/
    ui/
      forms/
        button.tsx
        __tests__/
          button.test.tsx          ← Unit test
      data-display/
        chart.tsx
        __tests__/
          chart.test.tsx
  stories/
    button.stories.tsx             ← Interaction test (play function)
    Performance.stories.tsx        ← Live performance dashboard
    performance-data.json          ← Generated by npm run perf
  lib/
    __tests__/
      utils.test.ts
      formatters.test.ts
  test/
    setup.ts                       ← Global JSDOM mocks
```

## 5. Unit Test Patterns (Vitest)

### Standard Pattern

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import { Button } from '../button';

describe('Button', () => {
  it('renders with default variant', () => {
    render(<Button>Click me</Button>);
    expect(screen.getByRole('button', { name: /click me/i })).toBeInTheDocument();
  });

  it('shows loading spinner and disables when isLoading', async () => {
    render(<Button isLoading loadingText="Saving...">Save</Button>);
    const btn = screen.getByRole('button');
    expect(btn).toBeDisabled();
    expect(screen.getByText('Saving...')).toBeInTheDocument();
  });

  it('fires onClick handler', async () => {
    const user = userEvent.setup();
    const onClick = vi.fn();
    render(<Button onClick={onClick}>Submit</Button>);
    await user.click(screen.getByRole('button'));
    expect(onClick).toHaveBeenCalledOnce();
  });
});
```

### Testing with Typed Stub Props (Recharts / Complex Types)

When a component's TypeScript type requires a prop that is injected at runtime by a parent (e.g., Recharts injects `payload` into legend/tooltip children), provide a minimal typed stub:

```tsx
// ✅ Typed stub — type-safe, no `as any`
const stubPayload: React.ComponentProps<typeof ChartLegendContent>['payload'] = [
  { value: 'sales', type: 'square', color: '#4f46e5', dataKey: 'sales', id: 'sales' },
];

render(<ChartLegendContent payload={stubPayload} />);
```

### Formatter Tests

```tsx
import { describe, it, expect } from 'vitest';
import { formatCurrency, formatDate, formatRelativeTime } from '../formatters';

describe('formatCurrency', () => {
  it('formats Indian rupee amounts', () => {
    expect(formatCurrency(1234567.89)).toBe('₹12,34,567.89');
  });

  it('returns "—" for null/undefined/NaN', () => {
    expect(formatCurrency(null)).toBe('—');
    expect(formatCurrency(undefined)).toBe('—');
    expect(formatCurrency(NaN)).toBe('—');
  });
});
```

## 6. Interaction Test Patterns (Storybook `play()`)

> **All story interaction test imports MUST use `storybook/test`** — never `@testing-library/react`.

```tsx
import { expect, within, userEvent, waitFor } from 'storybook/test';
```

> [!IMPORTANT]
> Never import from `@testing-library/react` or `@testing-library/user-event` in story files. Storybook 10 re-exports these through its own `storybook/test` shim to ensure browser compatibility with real Chromium execution.

### 6.1 Standard Pattern

```tsx
export const ClickButton: Story = {
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);
    const button = canvas.getByRole('button', { name: /submit/i });
    await userEvent.click(button);
    await waitFor(() =>
      expect(canvas.getByText(/success/i)).toBeInTheDocument()
    );
  },
};
```

### 6.2 Keyboard Interaction

```tsx
play: async ({ canvasElement }) => {
  const canvas = within(canvasElement);
  const input = canvas.getByRole('textbox');
  await userEvent.type(input, 'search term');
  await userEvent.keyboard('{Enter}');
  await waitFor(() => expect(canvas.getByText(/results/i)).toBeInTheDocument());
},
```

### 6.3 Waiting for Async State

```tsx
play: async ({ canvasElement }) => {
  const canvas = within(canvasElement);
  await userEvent.click(canvas.getByRole('button', { name: /load/i }));

  // Wait for loading to finish
  await waitFor(() =>
    expect(canvas.queryByText(/loading/i)).not.toBeInTheDocument(),
    { timeout: 3000 }
  );

  expect(canvas.getByText(/loaded data/i)).toBeInTheDocument();
},
```

## 7. Portal-Rendered Components (CRITICAL)

Radix UI components using `<Portal>` render **outside `canvasElement`** into `document.body`. Querying via `canvas.getByX(...)` will **always fail** for these.

**Portal components:** `Tooltip`, `HoverCard`, `Popover`, `DropdownMenu`, `ContextMenu`, `AlertDialog`, `Sheet`, `Dialog`, `Select` (options), `Command`

### ❌ Wrong

```tsx
await userEvent.click(trigger);
expect(canvas.getByRole('tooltip')).toBeInTheDocument(); // FAILS — not in canvas
```

### ✅ Correct — use `within(document.body)`

```tsx
await userEvent.click(trigger);
await waitFor(() =>
  expect(within(document.body).getByRole('tooltip')).toBeInTheDocument()
);
```

### Portal Role Reference

| Component | How to query |
|---|---|
| `Tooltip` | `within(document.body).getByRole('tooltip')` |
| `AlertDialog` | `within(document.body).getByRole('alertdialog')` |
| `Dialog` / `Sheet` | `within(document.body).getByRole('dialog')` |
| `DropdownMenu` | `within(document.body).getByRole('menu')` |
| `DropdownMenuItem` | `within(document.body).getByRole('menuitem', { name: /label/i })` |
| `Popover` / `HoverCard` | `document.body.querySelector('[data-radix-popper-content-wrapper]')` |
| `Select` options | `within(document.body).getByRole('option', { name: /value/i })` |
| `Command` items | `within(document.body).getByRole('option', { name: /value/i })` |

### Language Toggle (special case)

```tsx
// LanguageToggle renders its dropdown menu in document.body via portal
await userEvent.click(canvas.getByRole('button'));
await waitFor(() =>
  expect(within(document.body).getByRole('menu')).toBeInTheDocument()
);
await userEvent.click(within(document.body).getByRole('menuitem', { name: /hindi/i }));
```

### DateRangePicker (special case)

```tsx
// Calendar renders in Popover portal
await userEvent.click(canvas.getByRole('button', { name: /date/i }));
const body = within(document.body);
await waitFor(() => expect(body.getByRole('grid')).toBeInTheDocument());
await userEvent.click(body.getAllByRole('gridcell')[5]);
```

## 8. CSS Visibility vs DOM Presence

| Behaviour | Component Examples | Correct Assertion |
|---|---|---|
| Content **unmounted** when closed | `Collapsible`, `DropdownMenu`, `Dialog` | `not.toBeInTheDocument()` when closed |
| Content **hidden via CSS** (`height: 0`) | `Accordion` | `toBeInTheDocument()` (not `toBeVisible()`) |
| Content always in DOM | `Badge`, `Card`, `Progress` | `toBeInTheDocument()` or `toBeVisible()` |

> [!WARNING]
> **Never use `toBeVisible()`** on Accordion content. Radix uses `height: 0 + overflow: hidden` during close animation — `toBeVisible()` returns `false` even when the element is in the DOM and the assertion will be flaky.

## 9. Text Matching Guidelines

```tsx
// ❌ Fragile — fails if surrounding elements split the text node
canvas.getByText('Project Health Overview')

// ✅ Robust — partial regex, case insensitive
canvas.getByText(/project.*health/i)

// ❌ Duplicated text — fails when the same text appears in title + breadcrumb
canvas.getByText('Purchase Orders')

// ✅ Scoped to a semantic role
canvas.getByRole('heading', { name: /purchase orders/i })

// ❌ Strict string match — brittle against whitespace changes
canvas.getByText('  Save Changes  ')

// ✅ Trimmed regex
canvas.getByText(/save changes/i)
```

## 10. Component-Specific Gotchas

### Progress (Radix)

Radix `Progress` does **not** automatically set `aria-valuenow`. Do not assert on it:

```tsx
// ❌ Fails — Radix doesn't set aria-valuenow
expect(indicator).toHaveAttribute('aria-valuenow', '75');

// ✅ Assert on the visual indicator class
const indicator = canvas.getByRole('progressbar')
  .querySelector('[class*="bg-primary"]');
expect(indicator).toBeInTheDocument();
```

### ToggleGroup (Radix)

| `type` prop | Item `role` | Container `role` |
|---|---|---|
| `type="single"` | `radio` | `radiogroup` |
| `type="multiple"` | `checkbox` | `group` |

```tsx
// Single select
const group = canvas.getByRole('radiogroup');
const option = within(group).getByRole('radio', { name: /bold/i });
await userEvent.click(option);
expect(option).toHaveAttribute('data-state', 'on');

// Multi select
const option = canvas.getByRole('checkbox', { name: /italic/i });
await userEvent.click(option);
expect(option).toHaveAttribute('data-state', 'on');
```

### StatusBadge (unknown statuses)

Unknown `status` values fall back to the raw lowercase string — assert accordingly:

```tsx
// ❌ Wrong — "Suspended" (capitalized) is not rendered
canvas.getByText('Suspended')

// ✅ Correct — raw lowercase fallback
canvas.getByText('suspended')
```

### Tooltip (delay)

Always set `delayDuration={0}` in stories to eliminate the 700ms default hover delay:

```tsx
<TooltipProvider delayDuration={0}>
  <Tooltip>
    <TooltipTrigger asChild>
      <Button>Hover me</Button>
    </TooltipTrigger>
    <TooltipContent>Tooltip text</TooltipContent>
  </Tooltip>
</TooltipProvider>
```

### Chart (Recharts in JSDOM)

Recharts `ResponsiveContainer` depends on `ResizeObserver`. In JSDOM, SVG may not render. Assert on the `[data-chart]` container instead of SVG internals:

```tsx
// ❌ Fragile — SVG may not render in JSDOM/headless
expect(canvas.getByRole('img')).toBeInTheDocument();

// ✅ Robust — data-chart attribute is always present
const { container } = render(<ChartContainer config={config}>...</ChartContainer>);
expect(container.querySelector('[data-chart]')).toBeInTheDocument();
```

### PageHeader (duplicate text)

When `title` matches breadcrumb content, use `getByRole('heading')` to scope:

```tsx
// ❌ Fails — "Purchase Orders" appears in both heading and breadcrumb
canvas.getByText('Purchase Orders')

// ✅ Scoped
canvas.getByRole('heading', { name: /purchase orders/i })
```

### RoleEmptyState (Sheet portal)

`RoleEmptyState` uses a `Sheet` internally — its content is portal-rendered:

```tsx
await userEvent.click(canvas.getByRole('button', { name: /create/i }));
await waitFor(() =>
  expect(within(document.body).getByRole('dialog')).toBeInTheDocument()
);
```

## 11. JSDOM Global Mocks

All global browser API mocks live in `src/test/setup.ts` — do **not** add them ad hoc in individual test files.

```ts
// src/test/setup.ts

// matchMedia — required by Radix responsive hooks
Object.defineProperty(window, 'matchMedia', {
  writable: true,
  value: (query: string) => ({
    matches: false,
    media: query,
    onchange: null,
    addListener: vi.fn(),
    removeListener: vi.fn(),
    addEventListener: vi.fn(),
    removeEventListener: vi.fn(),
    dispatchEvent: vi.fn(),
  }),
});

// ResizeObserver — required by Recharts, Sidebar, ResizablePanelGroup
global.ResizeObserver = vi.fn().mockImplementation(() => ({
  observe: vi.fn(),
  unobserve: vi.fn(),
  disconnect: vi.fn(),
}));

// scrollIntoView — required by Radix Command, Select
Element.prototype.scrollIntoView = vi.fn();
```

### Per-Test Mocks (export-utils)

When mocking globals only for a specific test file, use `vi.stubGlobal` (auto-restored after each test):

```ts
// export-utils.test.ts
vi.stubGlobal('localStorage', {
  getItem: vi.fn(),
  setItem: vi.fn(),
  removeItem: vi.fn(),
});

vi.stubGlobal('location', {
  assign: vi.fn(),
  href: '',
});
```

## 12. CI Integration

### `ci.yml` — runs on every push/PR to `main`

```
Checkout → Setup Node → npm ci → Install Playwright → tsc --noEmit → npm run test → build-storybook
```

### `publish.yml` — runs on tag push `v*` or manual dispatch

```
Checkout → Setup Node → Verify tag vs package.json → npm ci → Install Playwright
→ tsc --noEmit → npm run test → build-storybook → Configure npm auth → npm whoami → npm publish
```

### Pre-publish Checklist (manual)

Before creating a tag:
1. Run `npm run test` — all 584 tests pass
2. Run `npx tsc --noEmit` — zero TypeScript errors
3. Run `npm run build-storybook` — static build succeeds
4. Run `npm run perf` — regenerate performance data
5. Bump version: `npm version patch|minor|major`
6. Tag: `git tag vX.X.X && git push --tags`

## 13. Known Limitations

| Issue | Status | Workaround |
|---|---|---|
| Recharts SVG in JSDOM | Known — SVG may not compose in headless | Assert `[data-chart]` container, not SVG elements |
| `aria-valuenow` on Radix Progress | Not auto-set by Radix | Assert indicator CSS class `[class*="bg-primary"]` |
| `StatusBadge` unknown statuses | Falls back to raw lowercase | Assert exact lowercase string |
| `export-utils.ts` FileReader paths | FileReader mock needed for blob lines 74–104 | Lines excluded from branch threshold |
| `@joshwooding/vite-plugin-react-docgen-typescript` | Warns on vite@8 peer — no functional impact | Will resolve when `@storybook/react-vite` updates the dep |
| `ChartLegendContent` payload prop | TS requires it; Recharts injects at runtime | Pass typed `stubPayload` in unit tests (see §5) |
